# mmirioma

MmiriOma: a smart water delivery and distribution platform for Enugu, Nigeria.

This is a monorepo containing a modular-monolith API and a web frontend:

| Path          | What                                                          |
| ------------- | ------------------------------------------------------------- |
| `backend/`    | FastAPI, SQLAlchemy 2 (async, asyncpg), Alembic               |
| `frontend/`   | React, TypeScript, Vite, Tailwind CSS                         |
| `compose.yaml`| Local PostgreSQL 16 + PostGIS 3.4                             |
| `CLAUDE.md`   | Engineering conventions (read before contributing)            |
| `docs/`       | Architecture (`docs/architecture/`) and feature docs (`docs/features/`) |

All commands below are Bash and work in Linux/macOS shells and **Git Bash on
Windows**. Run them from the repository root unless a `cd` is shown.

## Prerequisites

- Docker with Docker Compose v2 (`docker compose version`)
- Python 3.14
- Node.js 24 and npm

## 1. Environment variables

```bash
cp .env.example .env
# then edit .env: set POSTGRES_PASSWORD and put the same password in DATABASE_URL
```

The root `.env` is read by both Docker Compose and the backend. It is ignored by
Git and must never be committed. Only `.env.example` files are tracked.

| Variable            | Used by   | Required | Default                 | Notes |
| ------------------- | --------- | -------- | ----------------------- | ----- |
| `POSTGRES_PASSWORD` | Compose   | yes      | none                    | Local DB user password |
| `APP_ENV`           | backend   | no       | `development`           | `development`, `test` or `production` |
| `APP_DEBUG`         | backend   | no       | `false`                 | SQL echo + debug tracebacks; rejected in production |
| `DATABASE_URL`      | backend   | yes      | none                    | Must be `postgresql+asyncpg://user:pass@host:port/db`; URL-encode special characters |
| `FRONTEND_URL`      | backend   | no       | `http://localhost:5173` | Exact CORS origin (credentials allowed); must be `https` in production |
| `SESSION_SECRET`    | backend   | prod     | random per process      | 32+ chars, required in production |
| `SESSION_MAX_AGE_SECONDS` | backend | no    | `604800` (7 days)       | Absolute session lifetime |
| `SESSION_COOKIE_SECURE` | backend | no      | on in production only   | Must not be `false` in production |
| `SESSION_COOKIE_SAMESITE` | backend | no    | `lax`                   | `none` requires a secure cookie |
| `VITE_API_BASE_URL` | frontend  | prod     | `http://localhost:8000` (dev only) | Set in `frontend/.env.local` |

Generate a session secret:

```bash
python -c "import secrets; print(secrets.token_urlsafe(48))"
```

The backend validates configuration at startup and refuses to start with unsafe
production settings (debug on, missing/short secret, non-https frontend).

## 2. Database (Docker)

```bash
docker compose up -d          # start PostgreSQL/PostGIS on 127.0.0.1:5432
docker compose ps             # wait for "healthy"
docker compose logs -f postgres
docker compose down           # stop (data is kept in the postgres_data volume)
```

## 3. Backend

```bash
cd backend
python -m venv .venv
source .venv/bin/activate        # Git Bash on Windows: source .venv/Scripts/activate
pip install -r requirements-dev.txt

alembic upgrade head             # apply migrations
uvicorn app.main:app --reload    # http://localhost:8000
```

- API docs: <http://localhost:8000/docs>
- Liveness: `curl http://localhost:8000/api/v1/health`
- Readiness (checks the database): `curl http://localhost:8000/api/v1/health/ready`

### Migrations

Alembic lives in `backend/alembic/`. It derives a synchronous `postgresql+psycopg`
URL from `DATABASE_URL`, so there is no separate migration URL to configure.
Run these from `backend/` with the virtualenv active:

```bash
alembic upgrade head                              # apply all migrations
alembic current                                   # show applied revision
alembic history                                   # list revisions
alembic revision --autogenerate -m "add orders"   # create a migration from model changes
alembic check                                     # fail if models and migrations differ
alembic downgrade -1                              # roll back one revision
```

Always review autogenerated migrations before applying them. New model modules must
be imported in `backend/alembic/env.py` so autogenerate can see them.

### Staff accounts

Customers register through the API. Admin and driver accounts are created from
`backend/` with the virtualenv active (the password is prompted for):

```bash
python -m app.modules.auth.cli create-user --role admin --name "Your Name" --phone 080...
python -m app.modules.auth.cli deactivate --phone 080...   # also signs the account out
python -m app.modules.auth.cli activate --phone 080...
```

See [`docs/features/authentication.md`](docs/features/authentication.md).

## 4. Frontend

```bash
cd frontend
cp .env.example .env.local       # optional in development
npm install
npm run dev                      # http://localhost:5173
```

The home page shows whether the backend health endpoint is reachable.

## 5. Tests and checks

Backend (from `backend/`, virtualenv active):

```bash
ruff check .
ruff format --check .
pytest                           # unit tests; no database needed
```

Database integration tests are skipped unless `TEST_DATABASE_URL` is set. To run
them against the local Docker database (after `alembic upgrade head`):

```bash
TEST_DATABASE_URL="$(grep '^DATABASE_URL=' ../.env | cut -d= -f2-)" pytest
```

Frontend (from `frontend/`):

```bash
npm run lint
npm run typecheck
npm test
npm run build
```

## Continuous integration

`.github/workflows/ci.yml` runs on pull requests targeting `main`:

- **backend**: ruff lint and format check, `alembic upgrade head` and `alembic check`
  against a throwaway PostGIS service, then `pytest` including integration tests.
- **frontend**: lint, type check, Vitest, production build.
